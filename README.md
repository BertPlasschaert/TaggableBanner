# Taggable Banner

This code allows users to add their usernames to the repo banner.
Inspired by the way [timburgan](https://github.com/timburgan) creatively used github actions
to update his chess README.md. I wanted to flair up my own homepage by creating some kind of
guestbook. Give it a try [here](https://github.com/BertPlasschaert)!

## How does it work?

When the visitor clicks the link below the banner and creates the issue using the pre-filled values, a github action will start to run.
This action will interact with the python code in this repo and execute the following steps.

- Check in the `README.MD` file if the user has already added their tag.
  - If the tag already exists, communicate it using a comment under the issue and close it.
- Add the username to the `README.MD` and add the tag to the `banner.svg`
- Communicate this to the user using a comment under the issue and closing it.

The banner is an **.svg** file, generated by the `banner.py` file.
The SVG is ideal for this as it scales perfectly for every screen.
It is also a fairly nice interface to generate programmatically.
And I was able to use CSS within the SVG to make the banner respond to **light and dark mode**.

## Test it locally

Just pip install the repo using the following command:
`pip install git+https://github.com/BertPlasschaert/taggable_banner`

This provides two CLI commands:
A check to see if the username is already in the banner: `taggablebanner check "<username>"`
A command to add the username to the banner: `taggablebanner add "<username>"`

Use these two commands to test the code locally.
The github actions installs the same package and calls the same commands when an issue is opened.

## Add it to your own repo
Start by copying the workflow file from this repo into your own repo. 
You can find this file here: `.github/workflows/add_username.yml`

Make sure **issues** are **enabled**, and **actions** have **read and write permissions**. These need to be set in the repository settings.

You can copy the `README_example.md` file from the `examples\` folder to start working from.

Don't forget the update the link in the button to your repo.
The URL params in that link will prepopulate the issue body and title.


## How to make it your own

The title: `Hello` is a string value you can easily change.
Nothing except the bricks, cracks and splats are on-file SVG elements.
The bulk of your work will be to update the 'magic numbers' that position these elements.
I've implemented exclusion zones around the brick elements and title, no tags can spawn fully over them.
So if you change these elements, make sure to update accordingly..
Adding fonts is possible but you'll need to encode them using [this method](https://blog.frankel.ch/fonts-embedded-svg/) and create a config for them.
